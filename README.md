# جامع الفتاوى

محرك بحث ذكي في فتاوى المشايخ. يكتب السائل سؤاله بأي لهجة أو صيغة، فيُعرض له جواب كل شيخ منقولاً بألفاظه من موقعه الرسمي، وتحته رابط صفحة الفتوى الأصلية.

## الخدمات
| الخدمة | المكان |
|---|---|
| البحث العام في فتاوى كل المشايخ | الصفحة الرئيسية |
| سؤال موجّه لشيخ بعينه | صفحة الشيخ، أو قائمة الاختيار، أو بذكر اسمه في السؤال («وش رأي ابن باز في…») |
| فهم العامية وتحويلها للفصحى | تلقائي، ويظهر للسائل «فهمنا سؤالك هكذا» |
| مقارنة أقوال المشايخ | زر «قارن الأقوال» في النتائج |
| الأبواب الفقهية | /abwab |
| البحث المباشر في مواقع المشايخ | تلقائي عند عدم وجود الفتوى في المخزون، أو بزر «ابحث مباشرة» |
| الوضع الخاص للتجربة | `SITE_PASSWORD` |
| السؤال بالصوت | زر الميكروفون (كروم وسفاري وأندرويد) |
| الاستماع للفتوى | الصوتية الأصلية إن وُجدت، وإلا قراءة النص |
| مشاركة الفتوى | واتساب، إكس، نسخ الرابط، بطاقة صورة، مع معاينة للرابط في واتساب |

| فتاوى ذات صلة | تحت كل فتوى |

| لوحة الإدارة | /admin |

## لماذا يصل الجواب خلال ثوانٍ؟
البحث لا يتم في الإنترنت وقت السؤال، لأن ذلك يأخذ 20 إلى 60 ثانية. الخطوات:
1. **أداة الجمع** تقرأ خرائط مواقع المشايخ (sitemap) وتحفظ كل فتوى (العنوان، السؤال، الجواب، الرابط، الصوتية) في قاعدة بيانات محلية مع فهرس نصي عربي.
2. **وقت السؤال:** يبدأ بحث نصي فوري (أجزاء من الثانية)، وبالتوازي يحوّل نموذج سريع (Claude Haiku) السؤال إلى الفصحى ويستخرج المصطلحات الفقهية ويعرف الشيخ المطلوب (حدّه ~2 ثانية).
3. **الترتيب:** النموذج يختار من أفضل 15 نتيجة ما يجيب فعلاً عن السؤال (حدّه ~2 ثانية).
4. لكل خطوة ذكية مهلة صارمة. إذا تأخرت يكمل الموقع بالبحث النصي، فالجواب لا يتجاوز 5-6 ثوانٍ.

**بوابة الصلة:** لا تُعرض فتوى إلا إذا شاركت السؤال في جوهره، لا في كلمة عامة. كل كلمة في السؤال لها وزن حسب ندرتها في الفتاوى، فـ«الربا» أثقل بكثير من «أكل». والفتوى لا تمر إلا إذا طابقت الكلمة الأثقل وغطّت 60% من وزن السؤال على الأقل. والمرادفات مضبوطة في `server/arabic.js` (مثل الربا والفوائد، والشراب والجورب)، وتقدر تزيدها.
إذا لم توجد فتوى في الموضوع، يقول الموقع «لم نجد» بدل أن يعرض فتوى أخرى.

**الأمانة:** النموذج لا يكتب أي جواب. النص المعروض هو نص الفتوى المحفوظ من موقع الشيخ، ومعه رابطها دائماً.

## النشر المجاني على GitHub Pages (الطريقة الموصى بها)
الموقع كله يعمل من GitHub بلا خادم: مجاني، ولا ينام، والبحث يتم في متصفح الزائر خلال أجزاء من الثانية.
- **كل ليلة:** يجمع GitHub Actions فتاوى جديدة، ويحفظها في `data/corpus`، ثم يبني الموقع وينشره.
- **عند أي تعديل في الكود:** يُعاد نشر الموقع تلقائياً.

**الخطوات**
1. أنشئ مستودعاً **عاماً (Public)** في GitHub، وارفع كل ملفات المشروع (بما فيها مجلد `.github`). إذا كان عندك مستودع قديم فيه ملفات الموقع، احذفها أولاً.
2. **Settings ← Pages ← Build and deployment ← Source** واختر **GitHub Actions**.
3. **Actions** ← «جمع الفتاوى» ← **Run workflow**. بعد انتهائه (حتى ٥ ساعات) يظهر الموقع بالفتاوى على:
   `https://اسم-المستخدم.github.io/اسم-المستودع/`
   أو `https://اسم-المستخدم.github.io/` إذا سميت المستودع `اسم-المستخدم.github.io`.

**ما الذي لا يتوفر في نسخة GitHub Pages؟**
لأنه لا يوجد خادم: لا ذكاء اصطناعي، ولا بحث مباشر، ولا لوحة إدارة، ولا «الأكثر بحثاً». البحث يعمل بالفهم المدمج للعامية والمرادفات وبوابة الصلة. لتفعيل الذكاء الاصطناعي لاحقاً، استخدم النشر على Render بالأسفل.

## النشر على Render (مع الذكاء الاصطناعي)
اربط المستودع نفسه في Render (New ← Blueprint) وأضف `ANTHROPIC_API_KEY`. يعمل على الخطة المجانية: ينزّل قاعدة الفتاوى الجاهزة التي ينشرها الجمع الليلي في Releases، لكنه ينام بعد ١٥ دقيقة بلا زوار.

## النشر المدفوع (أسرع وبلا نوم)
خطة Starter في Render مع قرص دائم على `/var/data` و`DATA_DIR=/var/data`. وهنا يعمل الجمع من لوحة الإدارة مباشرة.

## التشغيل على جهازك
المتطلبات: **Node.js 22.13 أو أحدث** فقط، بدون أي مكتبات خارجية (قاعدة البيانات SQLite مدمجة في Node).

```bash
cp .env.example .env        # ضع مفتاح API وكلمة مرور الإدارة
npm run demo                 # (اختياري) بيانات تجريبية لتجربة الشكل
npm start                    # http://localhost:3000
```
بدون مفتاح API يعمل الموقع أيضاً: بحث نصي مع تحويل محلي لأشهر الكلمات العامية، ومساعد بردود جاهزة.

## جمع الفتاوى
من لوحة الإدارة `/admin`، أو من سطر الأوامر:
```bash
npm run crawl -- --sheikh binbaz --limit 100     # تجربة صغيرة أولاً
npm run crawl -- --limit 5000                    # كل المشايخ
npm run crawl -- --sheikh islamqa --ai           # مع تحليل ذكي للصفحات (أدق، وله تكلفة)
```
- الأداة تحترم robots.txt، وتنتظر 1.5 ثانية بين الصفحات (`--delay`)، ولا تعيد جمع صفحة سبق جمعها إلا مع `--refresh`.
- خيار `--ai` يستخرج السؤال والجواب بدقة من الصفحات المعقدة، ويكتب «خلاصة» لكل فتوى تظهر في المقارنة.
- شغّل الجمع دورياً (مثلاً cron أسبوعي) لإضافة الفتاوى الجديدة.

### المواقع المضبوطة حالياً
| الشيخ | الموقع | طريقة الجمع |
|---|---|---|
| ابن باز | binbaz.org.sa | يتتبع قوائم الفتاوى (مجموع الفتاوى، نور على الدرب، فتاوى الدروس، الجامع الكبير) ويلتقط روابط `/fatwas/{رقم}/…` |
| ابن عثيمين | binothaimeen.net | الموقع الجديد يُبنى بجافاسكربت، فيقرأ النص من `old.binothaimeen.net/content/{رقم}`، ويحفظ رابط الموقع الرسمي `binothaimeen.net/content/{رقم}` للزائر. يتخطى الدروس وشروح الكتب ويأخذ الفتاوى واللقاءات فقط |
| البراك | sh-albarrak.com | يمر على `/fatwas/{رقم}` من الأحدث إلى الأقدم |
| اللجنة الدائمة | alifta.gov.sa | ⚠️ **غير جاهز**: روابط الفتاوى القديمة في الموقع لم تعد تعمل، والموقع الجديد يُبنى بجافاسكربت. أضف نمط روابط الفتاوى الجديد في الإعدادات عند معرفته |

### قبل أول جمع حقيقي
اختبرت أداة الجمع على صفحات تحاكي هذه المواقع، لا على المواقع نفسها. فابدأ بتجربة صغيرة لكل موقع:
```bash
npm run crawl -- --sheikh binbaz --limit 20
npm run crawl -- --sheikh binothaimeen --limit 20
npm run crawl -- --sheikh albarrak --limit 20
```
وراجع النتائج في الموقع. إذا كان السؤال أو الجواب فيه زوائد من الصفحة:
- عدّل `extract` للموقع في الإعدادات: `questionLabels` (كلمات قبل السؤال)، و`answerLabels` (كلمات قبل الجواب)، و`drop` (سطور تُحذف)، و`end` (كلمات تنتهي عندها الفتوى).
- أو شغّل الجمع مع `--ai`. يحدد النموذج بداية السؤال والجواب ونهايتهما، ويقص البرنامج النص كما هو، فتبقى ألفاظ الشيخ دون تغيير.

### مدة الجمع الأول
لاحترام خوادم المواقع ينتظر 1.5 ثانية بين كل صفحة، فجمع عشرات الآلاف من الفتاوى يأخذ عدة أيام. شغّله على دفعات (مثلاً `--limit 3000` كل ليلة)، وكل تشغيل يكمل من حيث توقف السابق.

## إضافة شيخ أو موقع
من لوحة الإدارة (محرر المشايخ) أو `config/sheikhs.json`:
```json
{
  "id": "alshuraim",
  "name": "الشيخ فلان بن فلان",
  "short": "فلان",
  "aliases": ["فلان", "الشيخ فلان"],
  "about": "نبذة قصيرة",
  "color": "#2f4b6e",
  "site": {
    "domain": "example.com", "name": "موقع الشيخ",
    "sitemaps": ["https://example.com/sitemap.xml"],
    "seeds": ["https://example.com/fatwas"], "follow": ["^https://example\\.com/fatwas\\?page=\\d+$"],
    "ids": { "template": "https://example.com/fatwa/{id}", "from": 1, "to": 20000 },
    "include": ["^https://example\\.com/fatwa/\\d+"]
  }
}
```
`aliases` هي الأسماء التي يُذكر بها الشيخ في الأسئلة، وبها يتعرف الموقع على الشيخ المطلوب.
يكفي واحد من طرق الاكتشاف الثلاث (`sitemaps` أو `seeds` أو `ids`)، ويجرّبها البرنامج بهذا الترتيب.

## النشر
أي خادم يشغّل Node 22، مثل VPS أو Render أو Railway أو Fly.io:
- أمر التشغيل: `npm start`
- متغيرات البيئة: `ANTHROPIC_API_KEY` و`ADMIN_PASSWORD` و`DATA_DIR`
- **اجعل `DATA_DIR` على قرص دائم** (Persistent Disk) حتى لا تضيع قاعدة الفتاوى عند إعادة النشر.
- ضع الموقع خلف HTTPS (الميكروفون لا يعمل بدونه).
- لا يعمل على الاستضافات بدون خادم (Serverless) مثل Vercel، لأنه يحتاج ملف قاعدة بيانات دائماً.

## التكلفة التقريبية
كل سؤال جديد = استدعاءان قصيران لنموذج Haiku، وتكلفته زهيدة. الأسئلة المكررة تُحفظ 6 ساعات ولا تكلف شيئاً. خيار `--ai` في الجمع يكلف مرة واحدة لكل فتوى.

## ملاحظات
- يُستحسن مراسلة إدارات مواقع المشايخ وإبلاغهم بالمشروع، فهو يحيل الزوار إليهم برابط كل فتوى.
- حدود الطلبات: 20 بحثاً و12 رسالة للمساعد في الدقيقة لكل زائر (في `server/index.js`).
